# Android-версия калькулятора (APK)

Нативная обёртка над веб-калькулятором из `../calculator`: один и тот же код
работает и в браузере, и в приложении — на этапе сборки он копируется в `assets` APK
(задача Gradle `copyWebApp`), поэтому дублирования исходников нет.

**Готовый файл:** `../apk/progcalc-debug.apk` (~42 КБ)

| Параметр | Значение |
|---|---|
| package id | `com.jorkyer.progcalc` |
| название | Программируемый калькулятор |
| версия | 1.0 (versionCode 1) |
| minSdk / targetSdk | 24 (Android 7.0) / 34 (Android 14) |
| подпись | debug-ключ, APK Signature Scheme v2 |
| зависимости | нет (ни AndroidX, ни сторонних библиотек) |
| разрешения | не запрашивает, интернет не нужен |

## Установка на телефон

1. Скопируйте `apk/progcalc-debug.apk` на устройство (или скачайте из репозитория).
2. Откройте файл — Android попросит разрешить «Установку неизвестных приложений»
   для браузера/файлового менеджера. Это нормально: APK подписан debug-ключом
   и не проходил проверку Google Play.
3. При первом запуске Google Play Services может предложить обновить WebView —
   приложение использует системный компонент `Android System WebView`.

Проверить APK перед установкой (без Android SDK, нужен только Python 3):

```bash
python3 android/verify_apk.py apk/progcalc-debug.apk
```

Скрипт проверяет структуру ZIP, наличие подписи v2 и debug-сертификата,
разбирает двоичный `AndroidManifest.xml` (package, min/targetSdk, activity,
intent-filter), ищет код обёртки в dex и сверяет ассеты с исходниками в
`calculator/` по SHA-256. Всего 39 проверок.

## Сборка вручную

Нужны JDK 17 и Android SDK (platform 34). Локально:

```bash
cd android
echo "sdk.dir=$ANDROID_HOME" > local.properties   # путь к SDK
./gradlew assembleDebug
# результат: android/app/build/outputs/apk/debug/app-debug.apk
```

Или откройте папку `android/` в Android Studio и соберите
**Build → Build Bundle(s)/APK(s) → Build APK(s)**.

Свои ключи и `local.properties` в репозиторий не попадают — см. `android/.gitignore`.

## Сборка в CI

`.github/workflows/build-apk.yml` собирает APK на `ubuntu-latest` (там Android SDK
уже установлен) при изменении `android/**`, `calculator/**` или самого воркфлоу:

1. JDK 17 → `./gradlew assembleDebug`;
2. артефакт `progcalc-debug-apk` (доступен на вкладке Actions);
3. **и** коммит `apk/progcalc-debug.apk` + `.sha256` в ту же ветку — потому что
   артефакты Actions скачиваются с `*.blob.core.windows.net`, а APK из репозитория
   можно забрать обычным `git pull`.

Push в CI делается токеном `GITHUB_TOKEN` и новый прогон не запускает,
`apk/**` в фильтр путей не входит — зацикливания нет.

Ручной запуск: вкладка **Actions → Build APK → Run workflow**.

## Что делает обёртка

`MainActivity.java` — это `WebView` плюс то, чего WebView сам не умеет:

| Возможность | Зачем нужна калькулятору |
|---|---|
| `onJsPrompt` → нативный диалог с полем ввода | выбор регистра (`R+`/`R−`/`RS`/`RR`), метки, константы в режиме ПРГ, имени сохраняемой программы |
| `onJsConfirm` / `onJsAlert` | подтверждение «Удалить всю программу?», сообщения об ошибках |
| `onShowFileChooser` | кнопка «ИМПОРТ JSON» (`<input type="file">` в WebView иначе не работает) |
| JS-мост `Android.saveText()` | кнопка «ЭКСПОРТ JSON»: скачивание blob-ссылок в WebView недоступно, поэтому файл пишется в каталог приложения, а путь показывается тостом и в панели примеров |
| `saveState`/`restoreState` | программа и состояние не теряются при повороте экрана |
| `onKeyDown` (Back) | кнопка «Назад» сначала идёт по истории WebView |

Файлы экспорта попадают в
`/sdcard/Android/data/com.jorkyer.progcalc/files/progcalc-program.json`
(внешний каталог приложения, разрешение на хранилище не требуется).

В браузере тот же код работает как раньше: мост отсутствует, и экспорт идёт
через обычную blob-ссылку.

## Оформление

- Иконка — векторный `res/drawable/ic_launcher.xml` (тёмная панель, зелёный LCD,
  сетка клавиш). Бинарных PNG в репозитории нет; на API 24+ иконка отображается
  как обычный квадрат со скруглениями, а не как адаптивная маска.
- Тема `Theme.ProgCalc` наследуется от системной `android:Theme.Material.NoActionBar`,
  цвета совпадают с `calculator/css/style.css` (`#10131A` фон, `#0B1A12` LCD,
  `#FFB454` акцент) — statusBar и navigationBar сливаются с приложением.
- Вёрстка под телефон: в `calculator/css/style.css` есть media-запросы на 700px и 380px
  (крупные тач-цели, однотонная раскладка, укороченный листинг программы).

## Известные ограничения

- **Debug-подпись.** Для публикации в Google Play нужен release-APK/AAB, подписанный
  собственным ключом: `signingConfig` в `app/build.gradle` сейчас ссылается на debug.
  Ключ в репозиторий класть не следует — его добавляют через секреты CI или подписывают локально.
- **localStorage на `file://`.** Библиотека программ и настройки сохраняются, если
  WebView разрешает хранилище для file-оришина; в коде калькулятора все обращения к
  `localStorage` обёрнуты в `try/catch`, поэтому в худшем случае программы просто не
  переживут перезапуск, а сам расчёт работает всегда. Экспорт/импорт JSON при этом
  остаются надёжным способом переноса.
- **`prompt()` в режиме программирования.** Набирать константу цифрами в режиме ПРГ
  нельзя — цифры открывают диалог ввода константы целиком. Так задумано: шаг программы
  должен появляться сразу, а не по одной цифре.
